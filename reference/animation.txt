DOCUMENT TECHNIQUE · UI MOTION SYSTEM · React + Framer Motion + Tailwind CSS
L'objectif est de donner à VoxLingo une sensation de fluidité et de précision professionnelle, sans ralentir les tâches de doublage ni distraire l'utilisateur pendant le traitement vidéo.
La règle centrale : chaque animation doit communiquer un état, guider une action ou confirmer un résultat. Les animations décoratives restent rares, subtiles et désactivables.
1. Principes du système de mouvement
- Courbe standard : cubic-bezier(0.22, 1, 0.36, 1), une accélération initiale suivie d'une décélération douce.
- Durées : généralement 200–600 ms pour les transitions visuelles. Les animations continues, comme les ondes audio, suivent le média en temps réel.
- Déplacement : entre 2 et 12 px pour les transitions d'interface.
- Échelle : variations légères, généralement de 0.98 à 1.02.
- Opacité : privilégiée pour éviter les mouvements excessifs.
- GPU : privilégier transform et opacity plutôt que l'animation de dimensions, de marges ou de positions de mise en page.
- Cohérence : une même action doit toujours produire le même type de réponse visuelle dans tout le logiciel.
Tokens d'animation
Token	Durée	Utilisation
motion-fast	200 ms	Survol, focus, changement d'icône
motion-base	300 ms	Boutons, menus, notifications
motion-page	400 ms	Apparition des pages et panneaux
motion-emphasis	500 ms	Cartes, modales, comparateur
motion-celebration	600 ms	Confirmation finale, accent visuel
Courbe par défaut :
--ease-vox: cubic-bezier(0.22, 1, 0.36, 1);


Pour les animations répétées, les délais et durées peuvent être adaptés au contexte, notamment pour les ondes audio, le traitement IA et les particules de célébration.

L'anneau doit représenter la progression réellement communiquée par le backend. Il ne faut jamais afficher un pourcentage fictif pour donner une impression d'activité.
Pour les étapes qui ne fournissent pas de pourcentage précis, utiliser un état indéterminé — un arc animé — plutôt que d'inventer une progression.

Les animations d'onde doivent être basées sur les données du signal lorsqu'elles sont disponibles. Une onde décorative simulée peut servir de remplacement, mais elle ne doit pas être présentée comme une mesure réelle de l'amplitude.

E. Zone de dépôt
import { motion } from "framer-motion";
import { useState } from "react";
import { FileVideo } from "lucide-react";

export function VideoDropZone({ onFile }) {
  const [dragging, setDragging] = useState(false);

  return (
    <motion.div
      animate={
        dragging
          ? {
              scale: [1, 1.01, 1],
              borderColor: "#22D3EE",
              boxShadow: "0 0 24px rgba(124,92,255,0.18)",
            }
          : {
              scale: 1,
              borderColor: "#353B4B",
              boxShadow: "0 0 0 rgba(0,0,0,0)",
            }
      }
      transition={
        dragging
          ? {
              duration: 0.4,
              repeat: Infinity,
              ease: [0.22, 1, 0.36, 1],
            }
          : { duration: 0.2 }
      }
      onDragEnter={(event) => {
        event.preventDefault();
        setDragging(true);
      }}
      onDragOver={(event) => event.preventDefault()}
      onDragLeave={() => setDragging(false)}
      onDrop={(event) => {
        event.preventDefault();
        setDragging(false);

        const file = event.dataTransfer.files[0];
        if (file) onFile(file);
      }}
      className="flex min-h-64 cursor-pointer
        flex-col items-center justify-center
        rounded-2xl border-2 border-dashed
        bg-[#141821] p-8"
    >
      <FileVideo
        className="mb-4 h-10 w-10 text-violet-400"
        aria-hidden="true"
      />

      <p className="font-medium text-white">
        Déposez votre vidéo ici
      </p>

      <p className="mt-2 text-sm text-gray-400">
        MP4, MOV ou WebM
      </p>
    </motion.div>
  );
}


Important : ce composant illustre l'animation et l'événement de dépôt. L'implémentation finale doit aussi prévoir un champ fichier accessible au clavier, valider le format et la taille, et ne jamais considérer le nom ou l'extension comme une validation suffisante du contenu vidéo.

G. Respect de prefers-reduced-motion
Créer un composant commun pour éviter de répéter la logique d'accessibilité.
import {
  MotionConfig,
  useReducedMotion,
} from "framer-motion";

export function VoxMotionProvider({ children }) {
  return (
    <MotionConfig reducedMotion="user">
      {children}
    </MotionConfig>
  );
}

export function useVoxMotion() {
  const reduced = useReducedMotion();

  return {
    reduced: Boolean(reduced),
    transition: reduced
      ? { duration: 0 }
      : {
          duration: 0.3,
          ease: [0.22, 1, 0.36, 1],
        },
    pageInitial: reduced
      ? { opacity: 1 }
      : { opacity: 0, y: 8 },
  };
}


À appliquer dans l'application :
- Supprimer les déplacements, zooms, pulsations et particules non essentiels en mode réduit.
- Conserver les changements d'état indispensables : progression, erreurs, succès et sélection.
- Garder une progression fonctionnelle, mais sans rotation infinie décorative.
- Ne pas bloquer la lecture vidéo, le déplacement du curseur ou les interactions de l'utilisateur.
- Respecter également la préférence de réduction des animations pour les animations CSS.

Règles d'ingénierie
1. Une seule source de vérité par état. La progression IA vient du backend ; la lecture audio vient du lecteur ; le comparateur vient de sa position contrôlée.
2. Pas d'animations concurrentes sur un même élément. Combiner les transformations dans un seul composant Motion.
3. Nettoyer les animations continues. Annuler les requestAnimationFrame, écouteurs et abonnements quand le composant est démonté.
4. Respecter les performances desktop. Limiter les filtres de flou, les ombres très diffuses et les grandes quantités de particules.
5. Gérer les transitions interrompues. Un changement rapide de page, une annulation ou une erreur ne doit pas laisser un composant dans un état visuel incohérent.
6. Ne pas confondre animation et état métier. Une animation terminée ne signifie pas que le fichier est sauvegardé, exporté ou téléchargé.
7. Tester les interactions au clavier. Les mêmes états de focus et de sélection doivent être accessibles sans souris.
5. Critères d'acceptation avant livraison
Checklist QA Motion
0/12



[ ] Les huit écrans utilisent la même courbe et les mêmes tokens de durée.
[ ] Les pages apparaissent sans saut de mise en page.
[ ] Les boutons principaux ont un survol et un état pressé cohérents.
[ ] La zone de dépôt distingue clairement fichier accepté, fichier refusé et survol.
[ ] Les ondes audio suivent la lecture réelle ou sont explicitement présentées comme décoratives.
[ ] Les étapes du traitement reflètent les états réels du moteur IA.
[ ] Les squelettes disparaissent dès que les données sont disponibles.
[ ] Les toasts ne masquent pas les commandes importantes.
[ ] Le comparateur suit le pointeur sans retard.
[ ] La célébration de fin ne se répète pas à chaque rendu.
[ ] prefers-reduced-motion désactive les animations non essentielles.
[ ] Les animations restent fluides pendant la lecture vidéo et le traitement.

Décision finale : VoxLingo doit privilégier les animations fonctionnelles, courtes et prévisibles. Les seuls mouvements continus autorisés par défaut sont ceux qui représentent une activité réelle — lecture audio, curseur temporel ou traitement en cours — ainsi que de très légers accents visuels, désactivables lorsque l'utilisateur préfère réduire les animations.
